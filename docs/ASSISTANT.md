# Local course assistant

The Assistant view answers questions using material saved or automatically imported for a selected module. It runs through a local Ollama model, with no AI API key or per-request service charge. Downloading/installing the engine and model requires internet access; inference uses the fixed loopback endpoint `http://127.0.0.1:11434/api/chat`. It does not fall back to a cloud model or provider.

## Saved calendar questions

Explicit timing questions such as “When’s the next lecture?” check the selected module’s saved calendar directly, including when there are no PDFs or the local AI is offline. EN/DE/VI next-lecture, tutorial, exam and assignment timing phrases are recognized. Results use the earliest future open entry of the requested type, exclude completed/dismissed records, preserve date-only and review uncertainty, and display stale-source warnings. A missing entry means the local calendar has no matching record; it does not establish cancellation or the absence of a real class/deadline. This path does not call a model or fabricate dates from course PDFs. Broader course-content questions still use readable material and the local model.

## Use

1. Use the official [RWTH SyncMyMoodle app](https://app.rwth-aachen.de/syncmymoodle/) (Windows name: Sync-my-L2P) to download enrolled-course files. Complete university sign-in in that app; Gobbler never reads its credentials or tokens.
2. Connect each downloaded course directory once using `pnpm local --connect-material-folder <module-id> "<course-directory>"`. Start Gobbler before connecting a folder. The operator stores mappings in ignored `.wrangler/local/config.json`; no browser endpoint accepts filesystem paths. Select each course directory, not the shared semester root.
3. Open Assistant, select a module and ask a specific question. Compare the quotations, document names and page references. Material coverage by module lists readable document counts; unavailable text is excluded from those counts and from answers. PDFs needing attention lists affected paths, recovery guidance and a route to connected Sources. The library refreshes every minute while visible and on returning to the app; local AI readiness is checked again on return. Refresh material library checks immediately. Manual PDF/paste entry remains optional.
4. Today lists Dates to review across modules; Assistant lists them above the material list. Upcoming suggestions come first, past dates and unknown cutoff times are labeled, and OCR dates retain their warning. Same-day tasks in the same module are offered for explicit updating before creating another task. Opening a suggestion starts the existing task editor; saving remains explicit. Identical reviewed document keys reuse tasks, repeated candidate keys are omitted, and changed documents never silently overwrite a task.

The local runner reads mapped directories without following directory links, bounding walks to 3,000 entries/20 levels. It waits for stable files and processes one new/changed PDF per course per pass. Text extraction reads up to ten original pages per batch in an isolated process (30 seconds, 256 MB JavaScript heap). Image-only pages use at most two OCR pages per batch. A page that hits the output limit retries once with a higher repetition penalty (1.2); a second truncated response is still rejected. Derived progress is cached under the PDF hash, so interrupted reads resume without repeating completed pages. A disposable cache retains at most 64 documents; original downloads remain untouched. Pending rounds repeat after 15 seconds, ordinary rounds after a minute, and unchanged failures retry after ten minutes. Calendar checks and heartbeats run independently of the OCR loop.

Imports support PDFs up to 50 MB, 2,000 original pages and two million extracted characters. Completed text is stored as parts of at most 200 pages/500,000 characters, retaining original page numbers, module ownership and OCR provenance. All parts are bound to their original file together. A revised, missing, unreadable or unfinished file is excluded from answers and date suggestions; another available file can independently retain identical text. Manually saved material stays independent. Assistant shows processed/total pages separately from actionable file failures, and marks OCR-derived material, quotations and date suggestions. OCR suggestions still require explicit review and never become confirmed deadlines automatically. Limits: 50 suggestions per part and 100 returned per review request.

Disconnecting a local source stops its imports without removing original files or saved tasks. Reconnect explicitly with the same command; retained configuration does not silently reconnect it. Synced library entries are managed through their source instead of a Remove button. Full local backups include bindings and extracted text; retain original download directories and runner configuration separately.

Local file reads do not establish remote freshness. For automatic Windows downloads, enable the official app's **Save**, **Login on program startup**, **Synchronization on startup**, and **Close after synchronization**, then exit it to save settings. Run `./scripts/windows-material-sync.ps1 -AppPath "<installed Sync-my-L2P.exe>"` once. This schedules the official executable at Windows sign-in and every 30 minutes, using its own saved options. It reads no tokens, runs only while the user is signed in, does not wake the laptop and does not duplicate an existing scheduled instance. Expired university authentication or downloader prompts require attention in that app; Gobbler does not claim those remote checks succeeded. Remove with `./scripts/windows-material-sync.ps1 -Remove`. Linux/macOS can supply folders from the official downloader, but this Windows scheduling script does not configure their startup.

PDFs are read on the device. The library saves extracted text, not original binaries, in the local account database. The account bound remains 500 material parts and five million serialized characters. Manual browser uploads remain limited to 200 pages, 10 MB and 500,000 characters; automatic OCR/larger imports use connected folders. Editing manually extracted text removes page references. Identical content in the same module is reused. Material is isolated by account and module; deleting a course also deletes its material.

## Local OCR

On Windows, image-only pages are rendered with the built-in Windows PDF API and sent only to Ollama's fixed loopback `/api/generate` endpoint using `glm-ocr:latest` and the `Text Recognition:` prompt. The renderer runs without changing PowerShell execution policy. There is no cloud fallback, remote coursework upload or MarkItDown dependency. Blank pages without embedded images do not invoke OCR. Non-Windows text-PDF imports still work; scanned-page rendering currently reports a Windows requirement.

Install the separate OCR model once with `ollama pull glm-ocr:latest`. Qwen3 remains the course Q&A model. OCR requests are sequential, bounded to 120 seconds per page, use an 8,192-token context/6,000-token output bound and 1.1 repetition penalty, and reject incomplete/length-truncated responses. Images are resized to at most 1,600 pixels on the longest edge; the model is unloaded after each OCR request to release GPU memory. Temporary PDF copies are deleted after rendering. Only derived page text/provenance is cached. Recovery after an interrupted process may leave disposable temporary copies; these are not source files. The downloader's size filter must also permit the larger files; this PC's filter was aligned to 50 MB without changing authentication settings.

OCR is a transcription, not ground truth. Formulas, diagram labels and handwriting can be misread or omitted, even when quotations exactly match the OCR output. Compare the original page before relying on a formula or saving a date. Printed and handwritten real-page trials informed the backend choice; a broader independent accuracy evaluation has not been performed.

The assistant selects up to eight overlapping text excerpts by topic-word relevance, downweighting common EN/DE/VI question words and repeated filename matches while favoring less common terms in the actual excerpt. This is lexical retrieval, not exhaustive semantic search across a course. Cross-language questions, diagrams, mathematical notation and broad synthesis may need a more specific question or a relevant pasted excerpt. An answer can still misinterpret valid quotations. Matching tolerates PDF whitespace differences only and returns the original source substring; changes to words, numbers or punctuation still fail validation. Exact-quote validation establishes that evidence exists, not that every generated claim follows from it. Unknown/unsupported answers are explicit; partial or invalid structured responses are rejected. Verification failures ask for a narrower question; connectivity/timeouts ask the user to start Ollama and retry. It never updates tasks, invents authoritative deadlines, submits work, browses Moodle or executes source instructions.

Answers are not saved between visits. Course material text is included in full local SQLite backups; older backups remain verifiable. The existing Settings JSON export/merge workflow covers academic records but does not include the material library. Keep original documents. No encrypted backup workflow was added: the user explicitly declined that work.

## One local database runtime

The background runner sends fixed, account-scoped operations to Gobbler’s running API through a loopback-only endpoint. Requests require a purpose-specific key derived from the local session secret; arbitrary SQL and browser sessions do not grant access. Calendar checks also run in that same API runtime. This avoids separate workerd processes opening the same D1 file and failing to obtain session commit tokens during concurrent reads/writes. PDF extraction and original files remain local to the runner. The binding proxy is used only to load configuration secrets, not to query the live database.

## Local setup

Install [Ollama for Windows](https://docs.ollama.com/windows), then download the [Qwen3 4B Instruct model](https://ollama.com/library/qwen3:4b-instruct):

```powershell
ollama pull qwen3:4b-instruct
```

Add `LOCAL_AI_MODEL=qwen3:4b-instruct` to the ignored `.dev.vars` file and use Gobbler's local update procedure. Preserve existing session/feed secrets. Keep Ollama bound to loopback. The Windows installer adds its own sign-in shortcut; it is separate from Gobbler's runner. On Linux, start `ollama serve` locally and use the same model and setting. Linux GPU inference and Windows reboot with the new engine require separate hardware verification.

Assistant → Check local AI checks the configured installed model without loading it. A first answer may take up to a minute to load the model; requests stop after 90 seconds. Generation has bounded context and output, no tools and no mutable workflow access. If Ollama is stopped or the model is missing, saved coursework, reminders and calendar checks continue working. Start the engine and retry; no cloud fallback is attempted.

The local interface follows the account's EN/DE/VI language preference; material text and quotations stay in their original language. The answer requests that language from the model. The existing optional OpenAI deadline-extraction feature remains separate, requires explicit consent and a separately configured provider, and is not used by this assistant.

The installed Windows engine completed its first-install automatic update before final validation. Real source-based EN/DE/VI and unsupported-question checks passed, followed by an authenticated browser/backend/model round trip with valid page evidence. The first cold answer took 78 seconds; subsequent small questions took about two seconds. These synthetic checks do not establish quality across a full academic course. An additional acceptance check used automatically imported course PDFs and a real local-model answer with a validated original page quotation. Broader course questions, formulas and scanned documents still require further quality work.

## Evidence and retrieval

Numbered lecture filenames such as `segmentation1` are tokenized into topic words and numbers. Matching document titles add a bounded ranking bonus while actual text matches remain stronger. The local model selects existing excerpt IDs; Gobbler supplies the original excerpt text itself rather than asking the model to retype formulas. Invalid IDs, missing references, provider failures and truncated answers are rejected. Original PDF page numbers and OCR warnings remain attached. Exact excerpt identity does not prove that every claim in a generated explanation is supported; compare the answer with its source.
